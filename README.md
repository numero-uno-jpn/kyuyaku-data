手術・処置の前や 造影 CT 検査の前に「どの薬を、 何日前から 休薬するか」 を、 学会ガイドラインや PMDA 添付文書などの 一次資料に基づいて 整理した **オープンデータ** です。 参照アプリ・API・全件データを 無料で 公開しています。

## 簡単な使い方

1. [参照アプリ](https://numero-uno-jpn.github.io/kyuyaku-data/) を 開き、 検索欄に 薬の名前を 入れます。 一般名・商品名・後発品名の どれでも、 一部だけでも、 ひらがなでも、 多少の 打ち間違いや 表記ゆれ (「アスピリソ」「リバロキサバン」) でも 検索できます。 何も 当たらない 時は 「もしかして」 の 候補を 出します。
   `https://numero-uno-jpn.github.io/kyuyaku-data/?q=アスピリン` のように URL でも 検索できます。
2. 薬効分類の ボタン (抗血栓薬・糖尿病薬 など) で 絞り込むこともできます。
3. カードを 押すと、 休薬日数 (安全側の値)、 ガイドライン別の値と 値の出どころ、 根拠の 引用または抜粋、 出典 (一次資料へのリンク) が 表示されます。
4. 「内容をコピー」 で 要点を テキストで、 「リンクをコピー」 で その薬の ページの URL を 取り出せます。

詳しくは [使い方ページ](https://numero-uno-jpn.github.io/kyuyaku-data/guide.html) を ご覧ください。

## このリポジトリで 公開しているもの・していないもの

**ここで 公開しているのは 「データ」 です。** AI を 使って データを 作る部分は **非公開** です。

| | 内容 |
|---|---|
| **公開** (このリポジトリ) | 休薬データ (`data/`)、 静的 API (`v1/`)、 参照アプリ (`index.html`・`assets/`)、 仕様・説明 (`docs/` 等)、 公開データを 整形・配信する コード (`code/`) |
| **非公開** | AI を 使って データを 作る 部分 — 一次資料 (ガイドライン・添付文書) の AI による 読み取り・照合・判定の プログラムと 指示文、 変化の 監視の 設定、 作業用の 中間データ、 一次資料の PDF |

AI を 使う 部分を 公開できないのは、 **AI サービスの 呼び出しに 課金を 伴う 契約情報 (API キー 等) と その運用の 設定が 含まれる** ためです。 一次資料の PDF も、 各学会・製薬企業の 著作物なので 公開していません。 データが どう 作られ、 どう 誤りを 防いでいるかは、 この README の [データの作り方](#データの作り方) と [データを 正しく・網羅的に 更新し続ける仕組み](#データを-正しく網羅的に-更新し続ける仕組み) で 説明しています。

## 作者より — このデータを作った理由

忙しい外来で、 合剤 (配合錠) に 含まれていた 抗血小板薬に 気づかなかったことが あります。 見慣れない ホルモン薬を 見落としたことも あります。 こうした 見落としの 経験から、 人の 注意力だけに 頼らず、 確認を 支える 道具が 必要だと 感じました。 それが、 このデータを 作り始めた 原点です。

休薬の 確認は、 現場の 努力だけでは 防ぎきれない 構造的な 難しさを 抱えています。

- **薬の 名前が 多すぎる。** 1 つの 一般名に 先発品・後発品・配合剤の 商品名が 何十も 並びます。 「タケルダ」 に アスピリンが 含まれていると 即座に 分かる人は 多くありません。 休薬対象を 覚えるとは、 その何倍もの 商品名を 一般名と 結びつけて 覚え続けることです。
- **知見が 絶えず 更新される。** SGLT2 阻害薬 (周術期の 正常血糖ケトアシドーシス) や GLP-1 受容体作動薬 (麻酔導入時の 誤嚥) のように、 数年前には 意識されていなかった 推奨が 次々に 加わります。 DOAC は 薬ごと・腎機能ごとに 休薬期間が 違い、 ガイドラインも 学会ごと・版ごとに 値が 異なります。
- **チェックリストには 限界がある。** 網羅的な リストは 何ページにもなり 外来の 数十秒では 引けず、 一枚の 簡潔版は 網羅性と 最新性を 犠牲にします。 数年前に 作られたきりの リストが 現役で 使われている 現場も あります。
- **個人の 気合に 頼っている。** 看護師・麻酔科医・主治医が 何重に 確認しても、 「誰かが 見ているはず」 という 隙間から 漏れます。 漏れの 教訓は 個人の メモに 書き溜められ、 共有されないまま 消えていきます。

一剤ごとに 最新の 添付文書と 複数の ガイドラインを 突き合わせ、 どの資料の どこに 書いてあるかを 確かめる — この作業を、 医療者 一人ひとりが 毎回 繰り返すのは 無駄で、 危険でもあります。 そこで、 **根拠を たどれる 形で 整理した 休薬データを 一度 作り、 正しく 更新し続け、 誰でも 使えるように 公開する** ことにしました。

作るのは 想像以上に 骨の折れる 作業でした。 同じ薬でも ガイドラインごとに 出血リスクの 分類や 日数が 異なり、 版の 改訂で 値が 変わります。 機械的な 抽出 (AI による 読み取りを 含む) では、 表の 番号の ずれや、 添付文書に 書かれていない 日数を 添付文書由来と してしまう 誤りが 実際に 数多く 見つかりました。 そのため、 根拠として 「確認済み」 と するのは **原文と 実際に 照合できた ものだけ** と 決め、 AI に 原文を 読ませて 照合し、 その結果を 作者が 一件ずつ 確認しています。

休薬の 判断そのものは、 患者さん ごとの 病態を 踏まえた 医療者の 仕事です。 このデータが 担いたいのは、 その前段の 「思い出す」「調べ直す」 手間と 見落としを 減らすことです。 全国の どこかで、 一件でも 手術の延期や 合併症を 防ぐ 助けに なれば 幸いです。

## 目的

周術期の 休薬判断は、 薬の種類・手術の出血リスク・麻酔の方法 (全身麻酔か 区域麻酔か)・腎機能などによって 変わり、 根拠となる ガイドラインも 学会ごと・版ごとに 異なります。 現場では 複数の 資料を 突き合わせる 手間がかかり、 確認漏れは 手術の延期や 出血・血栓の 合併症に つながります。

このデータベースは、
- 薬ごとに **ガイドライン別の値を 並べて** 比べられる
- どの値も **一次資料の どこに 書いてあるか** (資料名・頁・表、 PDF の該当頁へのリンク) を たどれる
- その値が **ガイドラインに 直接書かれた値か、 クラス推奨の当てはめか、 計算値か** が 分かる

ことを 目指して 作っています。 医療安全に 役立つよう、 誰でも 自由に 使える形で 公開しています。

## 収録範囲

- **対象**: 周術期 (手術・処置・区域麻酔) と 造影 CT 検査前の **休薬** に関わる薬剤。 抗血栓薬、 糖尿病薬、 降圧・利尿薬、 抗リウマチ薬・免疫抑制薬 (生物学的製剤・JAK 阻害薬を含む)、 骨粗鬆症薬、 ホルモン製剤、 抗がん剤の一部、 精神・神経系、 サプリメントなど。 収載数は [`v1/meta.json`](https://numero-uno-jpn.github.io/kyuyaku-data/v1/meta.json) の `drug_count` を 参照してください。
- **主な一次資料** (例):
  - 日本: 日本麻酔科学会・日本区域麻酔学会・日本ペインクリニック学会「抗血栓療法中の区域麻酔・神経ブロックガイドライン」 (2016 初版・2026 改訂第 2 版)、 日本循環器学会 (抗血栓療法・不整脈薬物治療・SGLT2 阻害薬)、 日本消化器内視鏡学会、 日本糖尿病学会、 日本腎臓学会、 日本リウマチ学会、 日本皮膚科学会、 顎骨壊死検討委員会 ポジションペーパー、 日本医学放射線学会 (造影剤)、 PMDA 添付文書
  - 海外: ACC/AHA 2024 (非心臓手術の周術期管理)、 ESC 2022、 ASRA 2018、 ACR/AAHKS 2022、 BSR 2019、 KDIGO 2022、 ASA (GLP-1 受容体作動薬・サプリメント)、 FDA 添付文書 など
- **含まないもの**: 薬物相互作用、 術後の 再開時期の 網羅的な情報、 小児の用量別の扱い、 一次資料の 全文。

## データの作り方

1. **一次資料からの 抽出**: ガイドライン・添付文書から、 薬ごとの 休薬日数 (出血リスク別)・条件 (用量・腎機能等)・根拠の記載箇所を 抽出します。 ガイドラインの 版ごと (初版・改訂版) に 分けて 記録しています。
2. **原文との 照合**: 原文と 照合できた 出典 (AI が 原文を 読んで 照合し、 作者が 確認する 方針) は、 確認状況 (`verification_status`) を `verified` とし、 所在 (頁・表) と 引用または抜粋を 記録しています。
3. **表示用の値 (安全側) の 決定**: 一覧や 参照アプリで 大きく 表示する `display_*` は、 次の 順で 決めた **安全側 (長い方) の値** です。
   1. 現行版の ガイドラインの 値の 最大値 (旧版は 除外)
   2. ガイドラインに 記載が なければ、 PMDA 添付文書の 値の 最大値
   3. どちらも なければ、 作者の 採用値
4. **値の出どころの 区別** (`value_derivation`):

   | 値 | 意味 |
   |---|---|
   | `direct` | ガイドラインが その薬の 値を 直接記載 |
   | `class` | ガイドラインは 薬効クラス (例: 「SGLT2 阻害薬」) 単位で 推奨しており、 その値を 個々の薬に 当てはめた |
   | `derived` | ガイドラインの 「半減期の N 倍」 等の ルールから 作者が 計算した値 |
   | (なし) | 未分類 (PMDA 添付文書などの 手入力値) |

   **`direct` 以外は、 ガイドラインに その薬の 日数が 明記されているわけでは ありません。**
5. **出典の 確認状況** (`references[].verification_status`):

   | 値 | 意味 |
   |---|---|
   | `verified` | 原文と 照合し (AI が 原文を 読み、 作者が 確認)、 所在と 引用または抜粋を 記録した 出典 |
   | `helper_link` | 補助的な 参照先 (専門家の合意文書・関連資料など)。 日数の根拠としての 確認は していない |
   | `landing_only` | 資料の 入口ページへの リンク (該当箇所までは 特定していない) |
   | `unverified` | 未確認 |
6. **引用または抜粋**: 根拠の 透明性のため、 一次資料からの 引用または抜粋を 載せています (和文 300 字 / 英文 600 字を 超えるものは 抜粋、 ` … ` は 中略)。 一部、 参考資料・作者による 注記を 含みます。 正確な 記載は 必ず 原典で 確認してください。

詳しくは [データの作り方 (詳細)](docs/methodology.md) を ご覧ください。 抽出・照合の 手順、 値の 決め方、 確認状況の 判定基準、 自動の 検査、 限界を 説明しています。

## データを 正しく・網羅的に 更新し続ける仕組み

休薬データは 一度 作って 終わりでは ありません。 新しい 商品名・後発品の 発売、 ガイドラインの 改訂、 添付文書の 改訂、 新薬の 承認 — どれか 1 つを 見逃しても、 データは 静かに 古くなります。 一方で、 更新の たびに 誤りが 混入する 危険も あります。 このデータベースでは、 **「変化を 漏れなく 検知する」 仕組み** と **「誤りを 入れない」 仕組み** を 組み合わせ、 最後は **原文で 確認し、 作者が 承認する** という 三段構えで 運用しています。 その中心で 働いているのが AI です。

<p align="center"><img src="assets/update-flow.svg" width="720" alt="① 変化を検知する (毎月・自動、新しいガイドラインは AI が読み取り): 商品名・後発品、薬価基準、学会ガイドライン (Web・PDF)、PMDA 添付文書の改訂、PMDA 新規承認薬 → 通知または自動の更新提案 → ② 原文で確認し作者が承認して反映: AI が原文を読んで照合し、作者が差分と根拠を確認・承認、値・所在・引用を記録 → 変更のたびに → ③ 誤りを入れない (自動の検査): 引用と数値が原文にあるか、既存の値が意図せず変わっていないか、公開物の整合性 → すべて通過したものだけ → 正本から公開データ・API・参照アプリへ自動反映"></p>

### ① 変化を 漏れなく 検知する (毎月・自動)

| 監視対象 | 情報を 集める日 | 何を 検知し、 どうするか |
|---|---|---|
| **商品名・後発品** (KEGG 医薬品データベース) | 毎月 1 日 | 収載薬の 新しい 商品名・後発品名を 取得し、 **追加のみ** の 更新提案を 自動で 作成。 既存の 確定済み 名称の 削除・格下げが あれば 提案自体を 止める (安全装置)。 すべての 自動検査に 合格したものだけを 取り込み |
| **薬価基準** (厚生労働省) | 毎月 1 日 | 薬価基準 収載品目と 照合し、 新規収載・名称変更などの 差分を レポートとして 通知 |
| **学会ガイドラインの Web ページ** | 毎月 5 日 | 各学会の ガイドライン掲載ページの 変化 (新版の 掲載など) を 検知して 通知。 新版の 候補は 抽出の 下準備まで 自動で 行う |
| **ガイドライン PDF** | 毎月 7 日 | 監視対象の PDF (2026-10 時点 33 本) を 公開元から 取得し、 内容 (ハッシュ値と 本文) と 掲載ファイル名の 変化から 改訂を 検知して 通知。 新版を 検知したら 抽出まで 自動で 行う |
| **PMDA 添付文書** | 毎月 9 日 | 監視対象の 添付文書 PDF (2026-10 時点 113 件) の 内容 (ハッシュ値) を 比較し、 改訂を 検知したら 最新版を 取得して 通知 |
| **PMDA 新規承認薬** (PMDA メディナビの メール通知) | 配信の たび | PMDA から 届く 「承認情報 掲載の お知らせ」 メールを 毎日 自動で 取り込み (メール受信 → Google Apps Script → GitHub)、 AI が 周術期の 休薬に 関わる 可能性の ある 薬を 判定して 保存。 月 1 回の 承認ページに まとめて 作者に 示す (休薬データに 未収載か 既収載かも 表示) |

検知は 自動ですが、 **休薬日数を 自動で 書き換えることは しません**。 値の 変更は 必ず ② を 経ます。

**情報を 集める日に データが 更新されるわけでは ありません。** 集めた 変化は 月 1 回の 承認ページで 作者が 判断し、 原文で 確認してから 反映するため、 ガイドラインや 添付文書の 改訂から 反映まで **最大 3 か月程度** かかることが あります。

検知した 変化は、 毎月 1 回、 作者用の **承認ページ** に すべて まとめます (作者への 定期の 連絡は 月 1 通だけ。 監視の 失敗は その都度 知らせます)。 作者は 項目ごとに 「休薬データへの 追加を 検討する」 「対象外」 「見送り」 などを 選んで 判断し、 判断しなかった 項目は 翌月の 承認ページの 先頭に 引き継がれます。

#### AI の 役割 — AI の 発達で 初めて 実現した 網羅性

150 剤を 超える 薬 × 30 本を 超える ガイドライン × 数百の 添付文書 — この 規模の データを、 医師 1 人で 正確に 保ち続けることは、 AI なしには 不可能でした。 **このデータベースは、 AI の 発達に よって 実現しました。** AI は 次の 場面で 中心的な 役割を 担っています。

- **新しい ガイドラインの 読み取り**: 改訂を 検知すると、 AI が 数十〜数百頁の PDF から 周術期の 休薬に 関わる 頁を 探し出し、 薬ごとの 休薬日数・条件 (用量・腎機能 など)・所在 (頁・表)・引用を 構造化データに 抽出します。 人が 一から 読み通す 時間を、 確認の 時間に 振り向けられます。
- **原文との 照合**: 既存データの 根拠を 確かめる ときも、 AI が 一次資料の 原文 (PDF) を 実際に 読んで、 引用・頁・表番号・日数を 突き合わせ、 違いと 根拠を 作者に 示します。
- **新規承認薬の 判定**: PMDA メディナビから 届く 承認情報の メール通知を 毎日 自動で 取り込み、 周術期の 休薬に 関わる 可能性の ある 薬を AI が 拾い出し、 月に 1 回 まとめて 作者に 通知します (承認された 新薬が 実際に 使われ始めるまでには 時間が あるため、 月 1 回の 確認で 十分と 判断しています)。 AI が 挙げた 販売名・根拠の行は メール本文と プログラムで 照合し、 本文に ない 名前は 除外します。 メールに 書かれていない 一般名は 「AI 推定・未確認」 と 明示します。 新薬の 承認を 待つのではなく、 PMDA からの 通知を きっかけに 動く 設計です。

一方、 商品名の 収集・薬価基準・PDF や 添付文書の 改訂検知は、 AI ではなく 決まった 手順の プログラムで 行っています。 **決まった手順で 確実に できる 部分には AI を 使わない** のも、 誤りを 減らす 工夫の 一つです。

#### PDF と 図表を ずれなく 読む

休薬日数の 多くは、 ガイドラインの 本文ではなく **表や図** に 書かれています。 たとえば 「行 = 薬、 列 = 出血リスク別の 休薬日数」 の 表や、 薬ごとの 休薬期間を 棒で 示した 図です。 PDF の 表は 見た目が 整っていても、 文字として 取り出すと 行と列の 区切りが 崩れやすく、 **1 行・1 列 ずれただけで 別の薬の 日数を 記録してしまいます**。 添付文書に 多い 2 段組の PDF では、 左右の 段の 文字が 混ざって 読めなくなることも あります。 精度の 高い 読み取りは、 このデータの 正しさの 土台です。

- **段組みを 正しく 扱う 読み取り**: 2 段組の 添付文書は、 段組みを 認識できる 方法で 読み直しています (2026 年 7 月に 66 剤分を 是正)。 文字の 混線が 再び 紛れ込んでいないかは、 変更の たびに 自動で 検査します (③)。
- **表は 構造のまま 保存**: 表は 行と列を 保ったまま 取り出し、 一次証拠として 保存します。 「どの薬の 行の、 どの列の 値か」 を、 文章に 直した 引用に 頼らず 機械的に 追跡できます。
- **AI には 原本の 頁を そのまま 見せる**: AI には、 文字だけでなく 該当頁の 原本 PDF (表や図を 含む) を 渡して 読ませます。 抜き出した 頁の 番号は 元の PDF の 頁と 対応付けて 扱い、 頁の ずれを 防ぎます。
- **表と 項目番号は 画像で 目視確認**: 表の 行・列や 推奨の 項目番号は、 PDF を 画像に して 目で 確かめます。

#### ハルシネーション (AI の もっともらしい 誤り) を 防ぐ 仕組み

AI は、 原文に ない 数値や 引用を もっともらしく 作り出すことが あります (ハルシネーション)。 実際に、 表の 番号の ずれや、 添付文書に 書かれていない 日数を 「添付文書由来」 とする 誤りも 見つかりました。 そこで **「AI の 出力は 誤りうる」 ことを 前提に**、 次の 仕組みを 重ねています。

1. **2 通りの 読み方で 独立に 抽出する**: 同じ ガイドラインを、 異なる 指示文で 2 回、 互いの 結果を 見せずに 抽出します (必要に 応じて 章ごとに 分けて 読みます)。 片方だけの 思い込みは、 もう片方との 食い違いとして 表に 出ます。
2. **食い違いは 原文で 裁定する**: 2 つの 結果の 違いを 別の AI が 一覧にし、 違いに 関わる 頁だけを 原文 PDF から 切り出して、 AI が もう一度 原文を 読んで どちらが 正しいかを 判定します。 判定の 経緯は 記録として 残します。
3. **形式の 検査**: 最終的な 抽出結果が 決められた 形式 (スキーマ) に 合わなければ 採用しません。
4. **AI の 出力は 「未確認」 扱い**: 自動で 抽出された データは 「未確認」 として 扱い、 作者が 内容を 確認するまで 公開データには 反映しません。
5. **プログラムによる 原文照合** (③ で 変更の たびに 自動実行): ガイドラインから 抽出した 引用が 一次資料の 本文に 文字どおり 存在するか、 数値が 原文の中で その薬の 名前の 近くに 現れるかを、 AI ではなく プログラムで 検査します。 根拠の 見当たらない 数値の 疑いが 新たに 出たら 反映を 止めます。
6. **別の AI による 独立再抽出 (監査)**: 監査の 際には、 原文と 薬の 名前だけを 別の AI に 与えて 数値を 独立に 抽出させ、 既存データと 突き合わせます。
7. **「確認済み」 に できるのは 原文で 照合できた ものだけ**: 要約・検索結果・AI の 記憶は 根拠に しません。 AI が 原文を 読んで 示した 根拠を、 作者が 確認して 初めて 確定します。

### ② 原文で 確認し、 作者が 承認して 反映する

- 通知を 受けたら、 改訂後の 原文 (ガイドライン・添付文書) を 取得し、 該当箇所を **AI が 原文を 読んで 照合** し、 変更前後の 差分と 根拠 (原文の 該当箇所) を 作者に 示します。 **作者が 確認・承認した ものだけ** を 反映します。 要約・検索結果・記憶は 根拠に しません。
- 値と あわせて **所在 (頁・表番号) と 引用または抜粋** を 記録します。 ガイドラインから 抽出した 引用は 原文と 機械的に 照合し、 表や 項目番号は PDF を 画像で 確認します。
- ガイドラインは **版ごとに** 記録し、 旧版の値は 履歴として 残したうえで 表示用の値の 計算から 外します。
- 「確認済み (`verified`)」 に できるのは、 国内外の 添付文書と 学会・公的機関の 正式な ガイドラインだけです。 専門家の 合意文書などの 実務資料は 参考 (`helper_link`) に とどめ、 確認状況を 引き上げません。
- 根拠の ない 日数を 出典の 追加だけで 「確認済み」 に 見せることは しません。

### ③ 誤りを 入れない (変更の たびに 自動で 検査)

| 検査 | 内容 |
|---|---|
| **引用の 実在検査** | 記録した 引用が、 一次資料から 抽出した 本文に 実際に 存在するか |
| **数値の 逆照合** | 休薬日数などの 数値が、 原文中で その薬の 名前と 一緒に 現れるか。 根拠の 見当たらない 数値 (読み取りの 誤りの 疑い) が 新たに 出たら 失敗に する |
| **値の 回帰検知** | 全薬剤・全ガイドラインの 値を 記録した 基準と 突き合わせ、 値の 変化を 検出。 意図した 変更は 作者が 明示的に 承認して 基準を 更新する。 別名の 衝突 (同じ名前が 複数の 薬に 当たる) も 検出 |
| **添付文書の 抽出崩れ検知** | 2 段組 PDF の 読み取りで 起きる 文字の 混線などが 紛れ込んでいないか |
| **公開データの 検査** | 内部用の 項目が 混入していないか、 引用が 上限内か、 公開データが 正本と 一致しているか |
| **形式の 検査** | ガイドラインからの 抽出結果が 決められた 形式 (スキーマ) に 合っているか |
| **単体テスト** | 検索・表示などの 処理が 壊れていないか |

公開データ (`data/`)・API (`v1/`)・参照アプリへの 同期と 本番への 配置は、 これらの 検査に **すべて 合格した 場合だけ** 行います。 一つでも 不合格なら 反映されません。 コミットの 前にも 同じ 検査を 実行します。 このほか、 ブラウザで 画面を 操作する テストも 変更の たびに 実行しています。 反映の 履歴は [コミット履歴](https://github.com/numero-uno-jpn/kyuyaku-data/commits/main) で 確認できます。

### 利用者からの 報告

それでも 誤りや 古い記載が 残る 可能性は あります。 気づいた点は [誤りの報告](https://github.com/numero-uno-jpn/kyuyaku-data/issues/new?template=correction.md) から、 根拠となる 資料と 頁を 添えて お知らせください。 報告も ② と 同じ手順 (原文で 確認し、 作者が 承認) を 経て 反映します。

## データ構造

`data/washout_public_v1.json` は `_meta` (版・ライセンス・免責) と `drugs` (薬ごとの配列) から なります。 1 薬の例 (アピキサバン、 一部 省略):

```json
{
  "name": "アピキサバン",
  "category": "DOAC (直接経口抗凝固薬 / FXa阻害薬)",
  "aliases": ["apixaban"],
  "brand_names": ["エリキュース錠2.5mg", "エリキュース錠5mg"],
  "surgery": {
    "required": true,
    "display_high_risk_days_before": 3,
    "display_low_risk_days_before": 1,
    "high_risk_surgery_examples": ["脊髄外科", "脳神経外科", "心臓外科"],
    "low_risk_surgery_examples": ["皮膚生検", "歯科抜歯", "白内障手術"],
    "note": "…"
  },
  "contrast_ct": { "required": false, "display_days_before": null },
  "guideline_variations": {
    "surgery": [
      {
        "source": "JSA・JSRA・JSPC 2026 改訂第 2 版",
        "high_risk_days": 3,
        "low_risk_days": 0,
        "value_derivation": "direct",
        "dose_dependent_summary": "標準 or 高用量 3日, 低用量 1日",
        "source_location": "p.25 表 9 + p.26 解説 + 表 11",
        "source_url": "https://anesth.or.jp/files/pdf/guideline_kouketsusen_shinkeiblock.pdf",
        "quote_excerpt": "…"
      }
    ],
    "contrast_ct": []
  },
  "references": [
    {
      "source": "JSA・JSRA・JSPC",
      "title": "抗血栓療法中の区域麻酔・神経ブロックガイドライン",

      "location_in_source": "表 7 (p.23) + 5 章 推奨 (p.22)",
      "quote_excerpt": "…"
    }
  ]
}
```

主な項目:

| 項目 | 意味 |
|---|---|
| `surgery.display_high_risk_days_before` / `display_low_risk_days_before` | 出血リスクの 高い / 低い 手術の 前の 休薬日数 (**安全側の値。 利用時は こちらを 推奨**)。 `0` は 休薬不要、 `null` は 記載なし |
| `surgery.high_risk_days_before` / `low_risk_days_before` | 作者の 採用値 (表示用の値の 決定に 使う 第 3 候補) |
| `contrast_ct.required` / `display_days_before` | 造影 CT 前の 休薬の 要否 / 日数 |
| `guideline_variations.surgery[]` / `contrast_ct[]` | ガイドライン別の値。 `high_risk_days` / `low_risk_days` / `days`、 `value_derivation`、 `dose_dependent_summary` (用量・腎機能別の要約)、 `version_label` / `version_year`、 `source_location`、 `source_url`、 `quote_excerpt` |
| `references[]` | 出典。 `source` / `title` / `year` / `url` / `verification_status` / `location_in_source` / `quote_excerpt` / `quote_translation_excerpt` (英文の和訳) |
| URL の `#page=N` | PDF の 該当頁 (PDF の 頁番号で、 印刷頁とは 異なることがある) |

すべての項目の 説明は [docs/api.md](docs/api.md) に あります。

## API・全件データの使い方

| URL (`https://numero-uno-jpn.github.io/kyuyaku-data/` からの パス) | 内容 |
|---|---|
| `v1/meta.json` | データの版・更新日・収載数・ライセンス・免責 |
| `v1/drugs.json` | 全薬剤の 一覧 (休薬日数の要約と 詳細ファイルの パス `file`) |
| `v1/drugs/{一般名}.json` | 1 薬の 詳細 |
| `v1/lookup.json` | 一般名・別名・商品名・後発品名 (小文字) → 一般名の 配列 |
| `v1/search-index.json` | あいまい検索用の 索引 (`assets/search.js` と 組み合わせる) |
| **`https://kyuyaku-data.numero-uno-jpn.workers.dev/v1/search?q=…`** | **検索 API** (`?q=` に 答える。 下記) |
| `data/washout_public_v1.json` | 全件 (1 ファイル) |

- 認証・利用登録は 不要です。 どのサイトからでも 呼び出せます (CORS: `Access-Control-Allow-Origin: *`)。
- **商品名から 引くとき**は、 `lookup.json` で 一般名を 得てから `drugs/{一般名}.json` を 取得します。 1 つの 商品名が 複数の 一般名に 対応する場合 (配合剤 等) は 配列に 複数 入ります。

```bash
BASE=https://numero-uno-jpn.github.io/kyuyaku-data/v1

curl $BASE/drugs/アピキサバン.json
curl -s $BASE/lookup.json | jq -r '.lookup["エリキュース錠5mg"][]'      # → アピキサバン

# 全件
curl -O https://raw.githubusercontent.com/numero-uno-jpn/kyuyaku-data/main/data/washout_public_v1.json
```

```js
// ブラウザ / Node.js
const BASE = 'https://numero-uno-jpn.github.io/kyuyaku-data/v1';
const { lookup } = await (await fetch(`${BASE}/lookup.json`)).json();
const [name] = lookup['エリキュース錠5mg'.toLowerCase()] ?? [];
const { drug } = await (await fetch(`${BASE}/drugs/${encodeURIComponent(name)}.json`)).json();
console.log(drug.surgery.display_high_risk_days_before);   // 3
```

### 検索 API (`?q=`)

`https://kyuyaku-data.numero-uno-jpn.workers.dev/v1/search?q=アスピリン&limit=20` で、 一致した薬を **一致度の 高い順の 配列 (JSON)** で 返します (参照アプリと 同じ あいまい検索。 打ち間違い・表記ゆれも 吸収)。 各結果には 休薬日数 (安全側の値)・詳細 JSON の URL・参照アプリの ページの URL が 付きます。 0 件の 時は 「もしかして」 の 候補を `suggestions` で 返します。 認証不要・CORS 全開放。

```bash
curl -G https://kyuyaku-data.numero-uno-jpn.workers.dev/v1/search --data-urlencode "q=エンレスト"
# → {"query":"エンレスト","count":2,"results":[{"name":"バルサルタン",…},{"name":"サクビトリル・バルサルタン",…}],…}
```

応答の 項目・エラー・コード例は [検索 API の 仕様ページ](https://numero-uno-jpn.github.io/kyuyaku-data/search-api.html) (その場で 試せる 欄 付き) と [docs/api.md](docs/api.md#検索-api-q) を 参照してください。 Python 標準の `urllib` から 呼ぶ 場合は `User-Agent` を 指定してください (既定の 名乗りは 配信基盤で 拒否されます)。

### あいまい検索 (ブラウザ・プログラム内で 使う)

ネットワーク越しに 呼ばず 手元で 検索したい 場合は、 参照アプリと 同じ あいまい検索の 関数 [`assets/search.js`](assets/search.js) (外部ライブラリなし) と 索引 `v1/search-index.json` で、 打ち間違い・表記ゆれに 強い 検索が できます。 下の例は ブラウザ用です (Node.js では `search.js` を ダウンロードして `import` してください)。

```js
import { buildIndex, search } from 'https://numero-uno-jpn.github.io/kyuyaku-data/assets/search.js';
const BASE = 'https://numero-uno-jpn.github.io/kyuyaku-data/v1';
const index = buildIndex((await (await fetch(`${BASE}/search-index.json`)).json()).drugs);
search(index, 'アスピリソ');   // → [{ name: 'アスピリン', score: 63, term: 'アスピリン', kind: 'typo' }]
```

吸収する 違いと 得点の 詳細は [docs/api.md](docs/api.md#あいまい検索-ブラウザプログラム内で-使う) を 参照してください。

## 利用上の注意 (制限事項)

- **一般的な目安です。** 個々の患者 (腎機能、 血栓リスク、 ステント留置後の期間、 用量など) に 応じた 判断が 必要です。 ガイドラインの 条件 (用量別・腎機能別) は `dose_dependent_summary` や 引用を 確認してください。
- **出血リスクの 分類は ガイドラインごとに 異なります。** 区域麻酔・神経ブロックの ガイドラインと 一般手術・内視鏡の ガイドラインでは 想定する 手技が 違います。 表示用の値は それらの 最長値 (安全側) です。
- **休薬しないことが 推奨される 場合が あります** (例: 冠動脈ステント留置後の アスピリン継続)。 日数だけで 判断せず、 補足と ガイドラインの 推奨文を 確認してください。
- **更新の 遅れが ありえます。** ガイドラインや 添付文書の 改訂から 反映まで 最大 3 か月程度 かかることが あります (月 1 回、 作者が 確認・承認して 反映するため)。 データの版と 更新日は `meta.json` で 確認できます。
- **医療機器 (プログラム医療機器) では ありません。**
