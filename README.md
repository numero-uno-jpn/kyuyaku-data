# 休薬情報データベース (Kyuyaku Data)

手術・処置の前や造影 CT 検査の前に「どの薬を、何日前から休薬するか」を、学会ガイドラインや PMDA 添付文書などの一次資料に基づいて整理した **オープンデータ** です。参照アプリ・API・全件データを無料で公開しています。

## 簡単な使い方

1. [参照アプリ](https://numero-uno-jpn.github.io/kyuyaku-data/) を開き、検索欄に薬の名前を入れます。一般名・商品名・後発品名のどれでも、一部だけでも、ひらがなでも、多少の打ち間違いや表記ゆれ (「アスピリソ」「リバロキサバン」) でも検索できます。何も当たらない時は「もしかして」の候補を出します。
   `https://numero-uno-jpn.github.io/kyuyaku-data/?q=アスピリン` のように URL でも検索できます。
2. 薬効分類のボタン (抗血栓薬・糖尿病薬など) で絞り込むこともできます。
3. カードを押すと、休薬日数 (安全側の値)、ガイドライン別の値と値の出どころ、根拠の引用または抜粋、出典 (一次資料へのリンク) が表示されます。根拠を見直した薬には、作者解釈も表示されます。
4. 「内容をコピー」で要点をテキストで、「リンクをコピー」でその薬のページの URL を取り出せます。

詳しくは [使い方ページ](https://numero-uno-jpn.github.io/kyuyaku-data/guide.html) をご覧ください。

**ここで公開しているのは「データ」です。** AI を使ってデータを作る部分は **非公開** です。

## 作者より — このデータを作った理由

忙しい外来で、合剤 (配合錠) に含まれていた抗血小板薬に気づかなかったことがあります。見慣れないホルモン薬を見落としたこともあります。こうした見落としの経験から、人の注意力だけに頼らず、確認を支える道具が必要だと感じました。それが、このデータを作り始めた原点です。

休薬の確認は、現場の努力だけでは防ぎきれない構造的な難しさを抱えています。

- **薬の名前が多すぎる。** 1 つの一般名に先発品・後発品・配合剤の商品名が何十も並びます。「タケルダ」にアスピリンが含まれていると即座に分かる人は多くありません。休薬対象を覚えるとは、その何倍もの商品名を一般名と結びつけて覚え続けることです。
- **知見が絶えず更新される。** SGLT2 阻害薬 (周術期の正常血糖ケトアシドーシス) や GLP-1 受容体作動薬 (麻酔導入時の誤嚥) のように、数年前には意識されていなかった推奨が次々に加わります。DOAC は薬ごと・腎機能ごとに休薬期間が違い、ガイドラインも学会ごと・版ごとに値が異なります。
- **チェックリストには限界がある。** 網羅的なリストは何ページにもなり外来の数十秒では引けず、一枚の簡潔版は網羅性と最新性を犠牲にします。数年前に作られたきりのリストが現役で使われている現場もあります。
- **個人の気合に頼っている。** 看護師・麻酔科医・主治医が何重に確認しても、「誰かが見ているはず」という隙間から漏れます。漏れの教訓は個人のメモに書き溜められ、共有されないまま消えていきます。

一剤ごとに最新の添付文書と複数のガイドラインを突き合わせ、どの資料のどこに書いてあるかを確かめる — この作業を、医療者一人ひとりが毎回繰り返すのは無駄で、危険でもあります。そこで、**根拠をたどれる形で整理した休薬データを一度作り、正しく更新し続け、誰でも使えるように公開する** ことにしました。

作るのは想像以上に骨の折れる作業でした。同じ薬でもガイドラインごとに出血リスクの分類や日数が異なり、版の改訂で値が変わります。機械的な抽出 (AI による読み取りを含む) では、表の番号のずれや、添付文書に書かれていない日数を添付文書由来としてしまう誤りが実際に数多く見つかりました。そのため、根拠として「確認済み」とするのは **原文と実際に照合できたものだけ** と決め、AI に原文を読ませて照合し、その結果を作者が一件ずつ確認しています。

休薬の判断そのものは、患者さんごとの病態を踏まえた医療者の仕事です。このデータが担いたいのは、その前段の「思い出す」「調べ直す」手間と見落としを減らすことです。全国のどこかで、一件でも手術の延期や合併症を防ぐ助けになれば幸いです。

## 目的

周術期の休薬判断は、薬の種類・手術の出血リスク・麻酔の方法 (全身麻酔か区域麻酔か)・腎機能などによって変わり、根拠となるガイドラインも学会ごと・版ごとに異なります。現場では複数の資料を突き合わせる手間がかかり、確認漏れは手術の延期や出血・血栓の合併症につながります。

このデータベースは、
- 薬ごとに **ガイドライン別の値を並べて** 比べられる
- どの値も **一次資料のどこに書いてあるか** (資料名・頁・表、PDF の該当頁へのリンク) をたどれる
- その値が **ガイドラインに直接書かれた値か、クラス推奨の当てはめか、計算値か** が分かる

ことを目指して作っています。医療安全に役立つよう、誰でも自由に使える形で公開しています。

## 収録範囲

- **対象**: 周術期 (手術・処置・区域麻酔) と造影 CT 検査前の **休薬** に関わる薬剤。抗血栓薬、糖尿病薬、降圧・利尿薬、抗リウマチ薬・免疫抑制薬 (生物学的製剤・JAK 阻害薬を含む)、骨粗鬆症薬、ホルモン製剤、抗がん剤の一部、精神・神経系、サプリメントなど。収載数は [`v1/meta.json`](https://numero-uno-jpn.github.io/kyuyaku-data/v1/meta.json) の `drug_count` を参照してください。
- **主な一次資料** (例):
  - 日本: 日本麻酔科学会・日本区域麻酔学会・日本ペインクリニック学会「抗血栓療法中の区域麻酔・神経ブロックガイドライン」 (2016 初版・2026 改訂第 2 版)、日本循環器学会 (抗血栓療法・不整脈薬物治療・SGLT2 阻害薬)、日本消化器内視鏡学会、日本糖尿病学会、日本腎臓学会、日本リウマチ学会、日本皮膚科学会、顎骨壊死検討委員会ポジションペーパー、日本医学放射線学会 (造影剤)、PMDA 添付文書
  - 海外: ACC/AHA 2024 (非心臓手術の周術期管理)、ESC 2022、ASRA 2025 (第 5 版)、ACR/AAHKS 2022、BSR 2019、KDIGO 2022、ASA (GLP-1 受容体作動薬・サプリメント)、FDA 添付文書など
- **含まないもの**: 薬物相互作用、術後の再開時期の網羅的な情報、小児の用量別の扱い、一次資料の全文。

## データの作り方

1. **一次資料からの抽出**: ガイドライン・添付文書から、薬ごとの休薬日数 (手術のリスク別)・条件 (用量・腎機能等)・根拠の記載箇所を抽出します。ガイドラインの版ごと (初版・改訂版) に分けて記録しています。
2. **原文との照合**: 原文と照合できた出典 (AI が原文を読んで照合し、作者が確認する方針) は、確認状況 (`verification_status`) を `verified` とし、所在 (頁・表) と引用または抜粋を記録しています。
3. **表示用の値 (安全側) の決定**: 一覧や参照アプリで大きく表示する `display_*` は、次の順で決めた **安全側 (長い方) の値** です。
   1. 現行版のガイドラインの値の最大値 (旧版は除外)
   2. ガイドラインに記載がなければ、PMDA 添付文書の値の最大値
   3. どちらもなければ、作者の採用値
4. **値の出どころの区別** (`value_derivation`):

   | 値 | 意味 |
   |---|---|
   | `direct` | ガイドラインがその薬の値を直接記載 |
   | `class` | ガイドラインは薬効クラス (例: 「SGLT2 阻害薬」) 単位で推奨しており、その値を個々の薬に当てはめた |
   | `derived` | ガイドラインの「半減期の N 倍」等のルールから作者が計算した値 |
   | (なし) | 未分類 (PMDA 添付文書などの手入力値) |

   **`direct` 以外は、ガイドラインにその薬の日数が明記されているわけではありません。**
5. **出典の確認状況** (`references[].verification_status`):

   | 値 | 意味 |
   |---|---|
   | `verified` | 原文と照合し (AI が原文を読み、作者が確認)、所在と引用または抜粋を記録した出典 |
   | `helper_link` | 補助的な参照先 (専門家の合意文書・関連資料など)。日数の根拠としての確認はしていない |
   | `landing_only` | 資料の入口ページへのリンク (該当箇所までは特定していない) |
   | `unverified` | 未確認 |
6. **引用または抜粋**: 根拠の透明性のため、一次資料からの引用または抜粋を載せています (和文 300 字 / 英文 600 字を超えるものは文の区切りで切るか作者が選んだ抜粋、` … ` は中略・続きあり)。一部、参考資料・作者による注記を含みます。正確な記載は必ず原典で確認してください。
7. **作者解釈** (`author_interpretation`): 日数の根拠があいまいな薬 (手術の資料がなく内視鏡のクラス推奨だけ、など) は、原典と添付文書を読み直し、出典ごとの区分 (場面・薬剤名の有無・推奨の単位) と、薬全体の解釈を記録しています。このとき、次の原則で値を決めています。
   - 手術・区域麻酔の資料が何もない薬は、日数を空 (記載なし) にする
   - 資料が「原則継続、条件付きで休薬」とする薬は、高リスクに条件付きの目安、低リスクに継続 (0) を入れる
   - 添付文書が日数なしで休薬を求める薬は 1 日。別の薬・別の場面の値は使わず、補足に参考として残す。ただし休薬の理由が「手術で食事がとれないこと」の指示 (経口血糖降下薬の「手術前後は禁忌・不適」) は、絶食が始まる手術当日の休薬 (当日休薬) とする
   - ただし投与間隔が 1 週以上の製剤 (注射・内服を問わない) は、1 日を当てても意味がないため日数を当てない (「高リスク日数なし」)。手術の日程は投与のスケジュールに合わせて処方医と決める
   - ガイドラインの「半減期の N 倍」で計算する値は、ガイドラインが書いた半減期を使う。ただしそれが添付文書の記載の範囲から外れるときは、添付文書の代表値 (母集団解析の値があればその値) を使う
   - 半減期の 5 倍が 2 か月を超える生物学的製剤は、値はガイドラインのままとし、長い休薬による再燃の警告 (BSR 2019) を補足に書く

詳しくは [データの作り方 (詳細)](docs/methodology.md) をご覧ください。抽出・照合の手順、値の決め方、確認状況の判定基準、自動の検査、限界を説明しています。

## データを正しく・網羅的に更新し続ける仕組み

休薬データは一度作って終わりではありません。新しい商品名・後発品の発売、ガイドラインの改訂、添付文書の改訂、新薬の承認 — どれか 1 つを見逃しても、データは静かに古くなります。一方で、更新のたびに誤りが混入する危険もあります。このデータベースでは、**「変化を漏れなく検知する」仕組み** と **「誤りを入れない」仕組み** を組み合わせ、最後は **原文で確認し、作者が承認する** という三段構えで運用しています。その中心で働いているのが AI です。

<p align="center"><img src="assets/update-flow.svg" width="720" alt="① 変化を検知する (毎月・自動、新しいガイドラインは AI が読み取り): 商品名・後発品、薬価基準、学会ガイドライン (Web・PDF)、PMDA 添付文書の改訂、PMDA 新規承認薬 → 通知または自動の更新提案 → ② 原文で確認し作者が承認して反映: AI が原文を読んで照合し、作者が差分と根拠を確認・承認、値・所在・引用を記録 → 変更のたびに → ③ 誤りを入れない (自動の検査): 引用と数値が原文にあるか、既存の値が意図せず変わっていないか、公開物の整合性 → すべて通過したものだけ → 正本から公開データ・API・参照アプリへ自動反映"></p>

### ① 変化を漏れなく検知する (毎月・自動)

| 監視対象 | 情報を集める日 | 何を検知し、どうするか |
|---|---|---|
| **商品名・後発品** (KEGG 医薬品データベース) | 毎月 1 日 | 収載薬の新しい商品名・後発品名を取得し、**追加のみ** の更新提案を自動で作成。既存の確定済み名称の削除・格下げがあれば提案自体を止める (安全装置)。すべての自動検査に合格したものだけを取り込み |
| **薬価基準** (厚生労働省) | 毎月 1 日 | 薬価基準収載品目と照合し、新規収載・名称変更などの差分をレポートとして通知 |
| **学会ガイドラインの Web ページ** | 毎月 5 日 | 各学会のガイドライン掲載ページの変化 (新版の掲載など) を検知して通知。新版の候補は抽出の下準備まで自動で行う |
| **ガイドライン PDF** | 毎月 7 日 | 監視対象の PDF (2026-10 時点 33 本) を公開元から取得し、内容 (ハッシュ値と本文) と掲載ファイル名の変化から改訂を検知して通知。新版を検知したら抽出まで自動で行う |
| **PMDA 添付文書** | 毎月 9 日 | 監視対象の添付文書 PDF (2026-10 時点 118 件) の内容 (ハッシュ値) を比較し、改訂を検知したら最新版を取得して通知 |
| **PMDA 新規承認薬** (PMDA メディナビのメール通知) | 配信のたび | PMDA から届く「承認情報掲載のお知らせ」メールを毎日自動で取り込み (メール受信 → Google Apps Script → GitHub)、AI が周術期の休薬に関わる可能性のある薬を判定して保存。月 1 回の承認ページにまとめて作者に示す (休薬データに未収載か既収載かも表示) |

検知は自動ですが、**休薬日数を自動で書き換えることはしません**。値の変更は必ず ② を経ます。

**情報を集める日にデータが更新されるわけではありません。** 集めた変化は月 1 回の承認ページで作者が判断し、原文で確認してから反映するため、ガイドラインや添付文書の改訂から反映まで **最大 3 か月程度** かかることがあります。

検知した変化は、毎月 1 回、作者用の **承認ページ** にすべてまとめます (作者への定期の連絡は月 1 通だけ。監視の失敗はその都度知らせます)。作者は項目ごとに「休薬データへの追加を検討する」「対象外」「見送り」などを選んで判断し、判断しなかった項目は翌月の承認ページの先頭に引き継がれます。

#### AI の役割 — AI の発達で初めて実現した網羅性

150 剤を超える薬 × 30 本を超えるガイドライン × 数百の添付文書 — この規模のデータを、医師 1 人で正確に保ち続けることは、AI なしには不可能でした。**このデータベースは、AI の発達によって実現しました。** AI は次の場面で中心的な役割を担っています。

- **新しいガイドラインの読み取り**: 改訂を検知すると、AI が数十〜数百頁の PDF から周術期の休薬に関わる頁を探し出し、薬ごとの休薬日数・条件 (用量・腎機能など)・所在 (頁・表)・引用を構造化データに抽出します。人が一から読み通す時間を、確認の時間に振り向けられます。
- **原文との照合**: 既存データの根拠を確かめるときも、AI が一次資料の原文 (PDF) を実際に読んで、引用・頁・表番号・日数を突き合わせ、違いと根拠を作者に示します。
- **新規承認薬の判定**: PMDA メディナビから届く承認情報のメール通知を毎日自動で取り込み、周術期の休薬に関わる可能性のある薬を AI が拾い出し、月に 1 回まとめて作者に通知します (承認された新薬が実際に使われ始めるまでには時間があるため、月 1 回の確認で十分と判断しています)。AI が挙げた販売名・根拠の行はメール本文とプログラムで照合し、本文にない名前は除外します。メールに書かれていない一般名は「AI 推定・未確認」と明示します。新薬の承認を待つのではなく、PMDA からの通知をきっかけに動く設計です。

一方、商品名の収集・薬価基準・PDF や添付文書の改訂検知は、AI ではなく決まった手順のプログラムで行っています。**決まった手順で確実にできる部分には AI を使わない** のも、誤りを減らす工夫の一つです。

#### PDF と図表をずれなく読む

休薬日数の多くは、ガイドラインの本文ではなく **表や図** に書かれています。たとえば「行 = 薬、列 = 出血リスク別の休薬日数」の表や、薬ごとの休薬期間を棒で示した図です。PDF の表は見た目が整っていても、文字として取り出すと行と列の区切りが崩れやすく、**1 行・1 列ずれただけで別の薬の日数を記録してしまいます**。添付文書に多い 2 段組の PDF では、左右の段の文字が混ざって読めなくなることもあります。精度の高い読み取りは、このデータの正しさの土台です。

- **段組みを正しく扱う読み取り**: 2 段組の添付文書は、段組みを認識できる方法で読み直しています (2026 年 7 月に 66 剤分を是正)。文字の混線が再び紛れ込んでいないかは、変更のたびに自動で検査します (③)。
- **表は構造のまま保存**: 表は行と列を保ったまま取り出し、一次証拠として保存します。「どの薬の行の、どの列の値か」を、文章に直した引用に頼らず機械的に追跡できます。
- **AI には原本の頁をそのまま見せる**: AI には、文字だけでなく該当頁の原本 PDF (表や図を含む) を渡して読ませます。抜き出した頁の番号は元の PDF の頁と対応付けて扱い、頁のずれを防ぎます。
- **表と項目番号は画像で目視確認**: 表の行・列や推奨の項目番号は、PDF を画像にして目で確かめます。

#### ハルシネーション (AI のもっともらしい誤り) を防ぐ仕組み

AI は、原文にない数値や引用をもっともらしく作り出すことがあります (ハルシネーション)。実際に、表の番号のずれや、添付文書に書かれていない日数を「添付文書由来」とする誤りも見つかりました。そこで **「AI の出力は誤りうる」ことを前提に**、次の仕組みを重ねています。

1. **2 通りの読み方で独立に抽出する**: 同じガイドラインを、異なる指示文で 2 回、互いの結果を見せずに抽出します (必要に応じて章ごとに分けて読みます)。片方だけの思い込みは、もう片方との食い違いとして表に出ます。
2. **食い違いは原文で裁定する**: 2 つの結果の違いを別の AI が一覧にし、違いに関わる頁だけを原文 PDF から切り出して、AI がもう一度原文を読んでどちらが正しいかを判定します。判定の経緯は記録として残します。
3. **形式の検査**: 最終的な抽出結果が決められた形式 (スキーマ) に合わなければ採用しません。
4. **AI の出力は「未確認」扱い**: 自動で抽出されたデータは「未確認」として扱い、作者が内容を確認するまで公開データには反映しません。
5. **プログラムによる原文照合** (③ で変更のたびに自動実行): ガイドラインから抽出した引用が一次資料の本文に文字どおり存在するか、数値が原文の中でその薬の名前の近くに現れるかを、AI ではなくプログラムで検査します。根拠の見当たらない数値の疑いが新たに出たら反映を止めます。
6. **別の AI による独立再抽出 (監査)**: 監査の際には、原文と薬の名前だけを別の AI に与えて数値を独立に抽出させ、既存データと突き合わせます。
7. **「確認済み」にできるのは原文で照合できたものだけ**: 要約・検索結果・AI の記憶は根拠にしません。AI が原文を読んで示した根拠を、作者が確認して初めて確定します。

### ② 原文で確認し、作者が承認して反映する

- 通知を受けたら、改訂後の原文 (ガイドライン・添付文書) を取得し、該当箇所を **AI が原文を読んで照合** し、変更前後の差分と根拠 (原文の該当箇所) を作者に示します。**作者が確認・承認したものだけ** を反映します。要約・検索結果・記憶は根拠にしません。
- 値とあわせて **所在 (頁・表番号) と引用または抜粋** を記録します。ガイドラインから抽出した引用は原文と機械的に照合し、表や項目番号は PDF を画像で確認します。
- ガイドラインは **版ごとに** 記録し、旧版の値は履歴として残したうえで表示用の値の計算から外します。
- 「確認済み (`verified`)」にできるのは、国内外の添付文書と学会・公的機関の正式なガイドラインだけです。専門家の合意文書などの実務資料は参考 (`helper_link`) にとどめ、確認状況を引き上げません。
- 根拠のない日数を出典の追加だけで「確認済み」に見せることはしません。

### ③ 誤りを入れない (変更のたびに自動で検査)

| 検査 | 内容 |
|---|---|
| **引用の実在検査** | 記録した引用が、一次資料から抽出した本文に実際に存在するか |
| **数値の逆照合** | 休薬日数などの数値が、その薬の引用の中、または原文中でその薬の名前の近くに現れるか。自動で確かめられない値 (計算値・クラス推奨の値を含む) は、作者が原文を読んで根拠を記録したものだけを通す。記録のない値が出たら失敗にする |
| **値の回帰検知** | 全薬剤・全ガイドラインの値を記録した基準と突き合わせ、値の変化を検出。意図した変更は作者が明示的に承認して基準を更新する。別名の衝突 (同じ名前が複数の薬に当たる) も検出 |
| **添付文書の抽出崩れ検知** | 2 段組 PDF の読み取りで起きる文字の混線などが紛れ込んでいないか |
| **公開データの検査** | 内部用の項目が混入していないか、引用が上限内か、公開データが正本と一致しているか |
| **形式の検査** | ガイドラインからの抽出結果が決められた形式 (スキーマ) に合っているか |
| **単体テスト** | 検索・表示などの処理が壊れていないか |

公開データ (`data/`)・API (`v1/`)・参照アプリへの同期と本番への配置は、これらの検査に **すべて合格した場合だけ** 行います。一つでも不合格なら反映されません。コミットの前にも同じ検査を実行します。このほか、ブラウザで画面を操作するテストも変更のたびに実行しています。反映の履歴は [コミット履歴](https://github.com/numero-uno-jpn/kyuyaku-data/commits/main) で確認できます。

### 利用者からの報告

それでも誤りや古い記載が残る可能性はあります。気づいた点は [誤りの報告](https://github.com/numero-uno-jpn/kyuyaku-data/issues/new?template=correction.md) から、根拠となる資料と頁を添えてお知らせください。報告も ② と同じ手順 (原文で確認し、作者が承認) を経て反映します。

主な項目:

| 項目 | 意味 |
|---|---|
| `surgery.required` | 手術前の休薬の対象か。`true` で日数がすべて `null` の剤は、休薬の対象だが資料に日数の記載がない (休薬不要なら日数は `0`) |
| `surgery.display_high_risk_days_before` / `display_low_risk_days_before` | リスクの高い / 低い手術の前の休薬日数 (**安全側の値。利用時はこちらを推奨**)。`0` は休薬不要、`null` は記載なし (ただし次の `*_day_of` が `true` なら当日休薬) |
| `surgery.display_high_risk_day_of` / `display_low_risk_day_of` | `true` は安全側の値が **手術当日の休薬** (前日まで服用可) であること。このとき日数は `null` |
| `surgery.high_risk_days_before` / `low_risk_days_before` | 作者の採用値 (表示用の値の決定に使う第 3 候補) |
| `surgery.high_risk_day_of` / `low_risk_day_of` | `true` は作者の採用値が **手術当日の休薬** (日数は `null`) |
| `surgery.author_interpretation` | **作者による根拠の解釈** (原典の記述ではない)。休薬日数がどの資料のどの記述から来たか、根拠の弱さ等。根拠を見直した剤のみ、他は `null` |
| `contrast_ct.required` / `display_days_before` | 造影 CT 前の休薬の要否 / 日数 |
| `guideline_variations.surgery[]` / `contrast_ct[]` | ガイドライン別の値。`source` (略称) と `source_title` (正式名。ガイドラインのみ、添付文書等には無し)、`high_risk_days` / `low_risk_days` / `days`、原文が時間の値は `*_hours` / `hours`、手術当日の休薬は `*_day_of` / `day_of` (いずれも日数は `null`)、`value_derivation`、`dose_dependent_summary` (用量・腎機能別の要約)、`version_label` / `version_year`、`source_location`、`source_url`、`quote_excerpt` |
| `references[]` | 出典。`source` / `title` / `year` / `url` / `verification_status` / `location_in_source` / `quote_excerpt` / `quote_translation_excerpt` (英文の和訳) / `author_interpretation` (作者によるその出典の解釈: `context` 場面 (手術・区域麻酔・内視鏡・添付文書・その他)、`mention` 薬剤名の有無 (薬剤名 / なし)、`recommendation` 休薬の推奨の単位 (薬剤名 / クラス / なし)、`text`)。ガイドライン別の値を持つガイドラインは `guideline_variations` にあり、`references[]` にあるとは限らない |
| URL の `#page=N` | PDF の該当頁 (PDF の頁番号で、印刷頁とは異なることがある) |

すべての項目の説明は [docs/api.md](docs/api.md) にあります。

## API・全件データの使い方

| URL (`https://numero-uno-jpn.github.io/kyuyaku-data/` からのパス) | 内容 |
|---|---|
| `v1/meta.json` | データの版・更新日・収載数・ライセンス・免責 |
| `v1/drugs.json` | 全薬剤の一覧 (休薬日数の要約と詳細ファイルのパス `file`) |
| `v1/drugs/{一般名}.json` | 1 薬の詳細 |
| `v1/lookup.json` | 一般名・別名・商品名・後発品名 (小文字) → 一般名の配列 |
| `v1/search-index.json` | あいまい検索用の索引 (`assets/search.js` と組み合わせる) |
| **`https://kyuyaku-data.numero-uno-jpn.workers.dev/v1/search?q=…`** | **検索 API** (`?q=` に答える。下記) |
| `data/washout_public_v1.json` | 全件 (1 ファイル) |

- 認証・利用登録は不要です。どのサイトからでも呼び出せます (CORS: `Access-Control-Allow-Origin: *`)。
- **商品名から引くとき**は、`lookup.json` で一般名を得てから `drugs/{一般名}.json` を取得します。1 つの商品名が複数の一般名に対応する場合 (配合剤等) は配列に複数入ります。

```bash
BASE=https://numero-uno-jpn.github.io/kyuyaku-data/v1

curl $BASE/drugs/アピキサバン.json
curl -s $BASE/lookup.json | jq -r '.lookup["エリキュース錠5mg"][]'      # → アピキサバン

# 全件
curl -O https://raw.githubusercontent.com/numero-uno-jpn/kyuyaku-data/main/data/washout_public_v1.json
```

```js
// ブラウザ / Node.js
const BASE = 'https://numero-uno-jpn.github.io/kyuyaku-data/v1';
const { lookup } = await (await fetch(`${BASE}/lookup.json`)).json();
const [name] = lookup['エリキュース錠5mg'.toLowerCase()] ?? [];
const { drug } = await (await fetch(`${BASE}/drugs/${encodeURIComponent(name)}.json`)).json();
console.log(drug.surgery.display_high_risk_days_before);   // 3
```

### 検索 API (`?q=`)

`https://kyuyaku-data.numero-uno-jpn.workers.dev/v1/search?q=アスピリン&limit=20` で、一致した薬を **一致度の高い順の配列 (JSON)** で返します (参照アプリと同じあいまい検索。打ち間違い・表記ゆれも吸収)。各結果には休薬日数 (安全側の値)・詳細 JSON の URL・参照アプリのページの URL が付きます。0 件の時は「もしかして」の候補を `suggestions` で返します。認証不要・CORS 全開放。

```bash
curl -G https://kyuyaku-data.numero-uno-jpn.workers.dev/v1/search --data-urlencode "q=エンレスト"
# → {"query":"エンレスト","count":2,"results":[{"name":"バルサルタン",…},{"name":"サクビトリル・バルサルタン",…}],…}
```

応答の項目・エラー・コード例は [検索 API の仕様ページ](https://numero-uno-jpn.github.io/kyuyaku-data/search-api.html) (その場で試せる欄付き) と [docs/api.md](docs/api.md#検索-api-q) を参照してください。Python 標準の `urllib` から呼ぶ場合は `User-Agent` を指定してください (既定の名乗りは配信基盤で拒否されます)。

### あいまい検索 (ブラウザ・プログラム内で使う)

ネットワーク越しに呼ばず手元で検索したい場合は、参照アプリと同じあいまい検索の関数 [`assets/search.js`](assets/search.js) (外部ライブラリなし) と索引 `v1/search-index.json` で、打ち間違い・表記ゆれに強い検索ができます。下の例はブラウザ用です (Node.js では `search.js` をダウンロードして `import` してください)。

```js
import { buildIndex, search } from 'https://numero-uno-jpn.github.io/kyuyaku-data/assets/search.js';
const BASE = 'https://numero-uno-jpn.github.io/kyuyaku-data/v1';
const index = buildIndex((await (await fetch(`${BASE}/search-index.json`)).json()).drugs);
search(index, 'アスピリソ');   // → [{ name: 'アスピリン', score: 63, term: 'アスピリン', kind: 'typo' }]
```

吸収する違いと得点の詳細は [docs/api.md](docs/api.md#あいまい検索-ブラウザプログラム内で-使う) を参照してください。

## 利用上の注意 (制限事項)

- **一般的な目安です。** 個々の患者 (腎機能、血栓リスク、ステント留置後の期間、用量など) に応じた判断が必要です。ガイドラインの条件 (用量別・腎機能別) は `dose_dependent_summary` や引用を確認してください。
- **出血リスクの分類はガイドラインごとに異なります。** 区域麻酔・神経ブロックのガイドラインと一般手術・内視鏡のガイドラインでは想定する手技が違います。表示用の値はそれらの最長値 (安全側) です。
- **日数が空 (記載なし) の薬があります。** 手術・区域麻酔の資料に記載がない薬は、別の場面の値を当てはめず空にしています。事情は作者解釈をご覧ください。
- **休薬しないことが推奨される場合があります** (例: 冠動脈ステント留置後のアスピリン継続)。日数だけで判断せず、補足とガイドラインの推奨文を確認してください。
- **更新の遅れがありえます。** ガイドラインや添付文書の改訂から反映まで最大 3 か月程度かかることがあります (月 1 回、作者が確認・承認して反映するため)。データの版と更新日は `meta.json` で確認できます。
- **医療機器 (プログラム医療機器) ではありません。**
